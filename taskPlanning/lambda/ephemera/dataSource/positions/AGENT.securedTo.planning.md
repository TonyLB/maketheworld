# SecuredTo: a closed peer kind for "this holds it in place"

**Status:** opened 2026-10-28, redesigned the same day, re-scoped 2026-10-29 to a block with deterministic templates, and **re-scoped again 2026-10-30 to a first iteration that writes the full three-edge shape: `tie X to Y` writes `Custom(tied to)` justifying `SecuredTo`, and `untie X from Y` removes all three**. Nothing of `SecuredTo` itself is built. **Slice 0 (inventory, no code) done 2026-10-30; next step: Slice 1** (findings in [Progress](#progress)). The triple is written by a prototype `assignEdgeRelations` / `dissolveEdgeRelations` pair (SS-5) whose ref handling is ad hoc; the generic version is its own plan, [`AGENT.stableRefs.planning.md`](AGENT.stableRefs.planning.md), which this plan's prototype feeds. An implementation plan, per [`taskPlanning/AGENT.md`](../../../../AGENT.md).

**The shape.** `SecuredTo` is a closed peer kind with **no label**, same-graph and single-leg, directional (subject secured to object). It is never written bare: the first iteration writes it only as part of a triple, `Custom(tied to) -[Justifies]-> SecuredTo`, where the `Custom` edge carries the **manner** and the `Justifies` says that manner is why the thing is secured. `tie X to Y` writes the triple and `untie X from Y` removes it, through two prototype `Change` primitives (`assignEdgeRelations`, `dissolveEdgeRelations`, SS-5), as short-term keyword templates in the manner of the spread template, until the Plan LLM fallback inherits those routes. **`SecuredTo` blocks a move**; the `Custom` support edge that justifies it produces no facilitating dissolve of its own (the block covers it). Auto-lapse, the dissolve-and-judge path, further manner verbs and crossing supports are a **named later iteration** ([Later iteration](#later-iteration-lapse-judgment-and-more-manners)). The edge-terminal arm and `Justifies` shipped 2026-10-29 (rules in [`AGENT.contract.md` "Edge persist shape"](../../../../../lambda/ephemera/dataSource/positions/AGENT.contract.md#edge-persist-shape); the `Justifies` legality there is v1 scope, not its meaning). The capable version is booked in [Owed by the capable version](AGENT.edgeAbstractions.planning.md#owed-by-the-capable-version) and is **not** this plan.

## Goal

A member's hosting kind says where it sits (`On`, `In`, `Held`) or what it helps make up (`PartOf`, `SectionOf`). It says nothing about what *holds it there*. Being secured is a relation between two things, so it belongs on an edge: a plate glued to a table is `On` the table and `SecuredTo` it.

The split follows the closed-lexicon rule: a closed kind where the set can be enumerated (the *fact* of being secured, which deterministic code needs), an open label where the phrasing cannot be (the *manner*). The first iteration builds both halves and the `Justifies` between them, with one manner (`tied to`) so the shape is exercised end to end.

**Payoff, stated at the observable output (player commands, same-graph):** `tie the rope to the pole`, then `take the rope` is blocked ("secured": the code never reads the manner word); `untie the rope from the pole`, then the same `take` succeeds. At the graph, the tie leaves exactly three edges (`Custom(tied to)`, `SecuredTo`, and the `Justifies` from the first to the second) and the untie leaves none. A thing that is merely `Custom`-related to something it is moved away from (boots under a table) does not take the blocked path; it keeps today's challenged dissolve. *A `SectionOf` rope end tied to a pole (a crossing support, Owed item 6) is the later iteration.*

## What exists today (checked 2026-10-29, extended 2026-10-30)

- [`classifyInteractionUnderTransfer`](../../../../../lambda/ephemera/dataSource/positions/ludicGraph/expandValidate/interactionUnderTransfer.ts) is an exhaustive switch over `HostRelationalEdgeKind`. `Custom`, `ConnectedTo` and `Justifies` all return `defer`; `dissolve` is reserved with no producer. Adding `SecuredTo` is a compile error here until it picks a class.
- [`boundaryActionsInGraph`](../../../../../lambda/ephemera/dataSource/actions/commandAttempt/expandBoundaryChallenges.ts) turns every `defer` boundary edge into a facilitating dissolve with a `CustomEdgeChallenge`, and **throws** for a `defer` edge that is not `Custom`. Under the triple, the `Custom(tied to)` edge is itself a boundary edge when the rope moves, so this function must **skip a `Custom` edge that justifies a `SecuredTo`** (found by `edgeId` through the graph's `Justifies` edges), or the support would be dissolved while the take is refused. A `Justifies` is never a boundary edge: both its terminals are edges.
- **The block has a precedent.** `attemptActionsFromTransfer` puts an `ExitEdgeChallenge` on the **primary** action when the mover touches an exit, and the take abstains. A `SecuredTo` block is the same mechanism with its own challenge type, not a new action.
- [`matchSpreadTemplate.ts`](../../../../../lambda/ephemera/dataSource/actions/enrich/objectManipulation/plan/matchSpreadTemplate.ts) is the pattern for the templates: `defineAttemptTemplate` with a closed verb map, `CommandAttempt.create(kind, command, actions, narrationUnits)`, minted ids (`mintActionId`, used for `presenceUuid`), and a comment that the LLM Plan fallback replaces it. It is registered by adding it to `PLAN_TEMPLATES` in `planSkeleton.ts` (order matters; granules derive from the list). Per the actions contract an attempt's kind is the template's name, and a peer relation is `relation`.
- **The kernel can already do each piece of the triple, but Plan cannot say it.** `assignEdgeId` is a kernel step (caller-minted id on a stored single-leg edge). `ExecutorEstablishRelationStep` types its endpoints as `EphemeraLudicTerminalId`, which includes an edge terminal, **but `hostsOf` in `applyStepSequenceCore.ts` returns `[]` for an edge terminal**, so an `establishRelation` of a `Justifies` comes back `stale` (`staleRelationalCandidate`). And a `Change` (the Plan-level step) names grounded referents, which cannot be edges, with no `Change` form of `assignEdgeId`. Writing the triple needs a new `Change` primitive lowered to kernel steps (SS-5). The `extend` primitive is the precedent: about ten sites in six files (`planStep`, `groundChange`, `executor`, `attemptCandidates`, `stampCandidateReferents`, `commitAttempt`); **`extend` is not lowered in the executor** (it returns "no executor lowering") but at commit, in `commitAttempt`'s `buildExtendFragment`, which reads the object's graph and calls the pure `extendSteps` (Slice 0 correction; see Progress). `applyRelationalPatch` throws on removing an absent edge, so an optional dissolve (`mustBePresent: false`) needs handling before or at the kernel.
- **Dissolve takes referrers.** A `dissolveRelation` step removes every edge naming the dissolved `edgeId`, to a fixpoint (`withoutDanglingEdgeReferrers`). So `untie` dissolving `SecuredTo` takes the `Justifies` with it, and then dissolving the `Custom` leaves nothing; no auto-lapse is needed because `untie` removes all three explicitly. (Dissolving the `Custom` alone leaves a bare `SecuredTo`: "secured, manner unstated". That is the lapse question, deferred.)
- Sites that list the peer kinds by hand: `interactionUnderTransfer.ts` (exhaustive), `expandBoundaryChallenges.ts` (the throw), `applyDeparture.ts` (a second consumer of the classifier, Slice 0), `publishedEvents.ts` `RELATION_INSTRUCTION_KINDS` (`Custom`, `ConnectedTo` only), `mergeReducer.ts`, `presenceSubGraph.ts`, `presenceParent.ts` and `factsForStep.ts` (each special-cases `ConnectedTo`; Slice 0 confirmed `SecuredTo` takes the default path in all four), `expandSameHost.ts` (the `Custom`-only peer branch; a non-`Custom` kind errors, which the new primitives never reach), `applyStepSequenceCore.ts` (the `ConnectedTo` legality hook, where a `SecuredTo` same-graph refusal would sit), and `mtw-wml` `dataTypes/ludicEdge.ts` (the wire kind tuples). `STORED_RELATIONAL_EDGE_KINDS` drives the guards, so those need no edit.
- The contract's rule on peer relations ([*Relation kinds*](../../../../../lambda/ephemera/dataSource/positions/AGENT.contract.md#relation-kinds)): no deterministic parse of a peer relation; `Custom` comes only from the LLM Plan fallback. The templates are the first deterministic producer of a peer kind, and the manner-not-physics paragraph there is what `SecuredTo` partly overturns.

## Design record (condensed)

- **Placement, securing and composition separate.** Unglue the plate and it is an ordinary thing `On` the table. Removing a `PartOf` member is detaching or breaking it, which is the separate separability question.
- **Precondition versus consequence.** A **precondition** blocks a move until something is done. A **consequence** lets the move happen and changes something else (the rake falls). `SecuredTo` is the deterministic precondition; every other peer relation touching a moved thing goes to reasoning. The idea that other peer relations "could dissolve freely" was **withdrawn**.
- **Block, not dissolve-and-judge (iteration 1).** A `SecuredTo` on a boundary edge yields no facilitating action. It puts a challenge on the primary action and the move abstains until the edge is gone. Unsecuring is the player's own command (`untie`).
- **The manner is a separate edge, the secured fact is the block.** The code that blocks reads `SecuredTo` and never the label; the `Custom(tied to)` edge is what a later reasoning tier reads to decide how one might get free of it. The triple is written whole by one operation, so a `SecuredTo` made by `tie` always has its support.
- **Member to its own host's root.** A tag tied to its suitcase is a peer edge from the member to the host's root inside the host's graph. Nothing forbids it today. Untested (Slice 0).

## Later iteration: lapse, judgment and more manners

Deferred together, by the user's call (2026-10-29), because each is an automation or a richer form of the first iteration. Shelve in `AGENT.implementation.md` when this plan is deleted (Slice 4); none of it is an Open row. *(The support edge and the `Justifies` step, deferred in the earlier scoping, are now in the first iteration.)*

- **Auto-lapse.** Removing a `Justifies` that leaves the justified edge with no remaining supports removes the justified edge in the same apply, in the `withoutDanglingEdgeReferrers` fixpoint. `Justifies`-generic, OR only, v1 caveat. Open then: a `SecuredTo` that was never given a support persists as "secured, manner unstated", so only losing the last support lapses it.
- **Dissolve-and-judge.** A `SecuredTo` produces the facilitating dissolve of its supports (the existing `Custom` dissolve with its evaluator challenge) and "untie the rope" unsecures *as a judged action* rather than a player's own unconditional command. Whether a missing means to unsecure (no knife) refuses outright or goes to the evaluator is the Coyote rule (outcomes are genre-dictated, reject only the physically impossible), so likely evaluator.
- **More manner verbs.** `glue`, `nail` and the rest (templates now, the Plan LLM later), writing the same triple with a different label.
- **Crossing supports.** Owed item 6 in the edge-abstractions plan.
