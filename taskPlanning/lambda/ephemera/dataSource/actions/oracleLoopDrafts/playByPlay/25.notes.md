# Play-by-play draft 25: the reference kept, the examples in the input's shape

Step 2 of the item standing plan (`AGENT.itemStanding.planning.md`, retired 2026-11-21; its record in the [oracle loop plan](../../AGENT.oracleLoop.planning.md#recommended-order)'s Slice 4.5). [`25.ask.txt`](25.ask.txt) (`5f3f20db`, 7,836 characters) is draft 24's ask ([24.ask.txt](24.ask.txt)) with every example in the input's own shape, one example added, and the Role and Task reworded. The render's target label is renamed: `The step asked about: <path>` (was `The step to expand: <path>`).

**Status:** written 2026-11-20; batch 48 not yet run.

## Why

- **The record's revision has nowhere it's shown.** Batches 44 to 47 put OC-6/command's grounded revision into a one-entry `steps` 5 of 12 times, and into the record's `says` 2 of 12. 8 of 9 replies open "broken down into smaller steps" ([24.notes.md](24.notes.md#results-2026-11-20-batch-47)). The label "The step to expand:" presumes an expansion, and the one example that revises (the coat) also expands. An example alone would pull against the instructions' plain wording (the user, 2026-11-20), so the label, the Role and the example change together.
- **The examples weren't the input's shape.** Each was a text paragraph (`Step: <says>, with the intent <intent>. … The detail asked for: …`). None had a `The plan:` listing or a path reference, so the model never saw an example of the shape it is given. The reference by path stays. It was the design's point: list the steps with ids, then refer to one. Batch 45 replaced it with the step's text, which lost OC-1b and the concession cell. Batch 46 put the path back and both returned ([24.notes.md](24.notes.md#batch-46-fixes-1-and-2-with-the-path-line)). This answers the booked "clean target line" item: the rename goes ahead, and the text line is closed.
