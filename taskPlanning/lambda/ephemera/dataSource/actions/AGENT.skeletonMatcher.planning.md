## Goal

Replace the template matcher and the stages around it with one structure built to be solid, rather than repaired one bug at a time. Rungs 12 and 13 got the matcher to "not actively broken" by a run of local fixes, each correct where it was made, each putting a decision in whichever stage saw the symptom (see [What exists](#what-exists-read-from-code-2026-10-25)).

**The principle (user, 2026-10-25): split at maximum resolution, then let the matcher reconstitute larger aggregates.**

- The command is cut at every dividing word (`on`, `in`, `at`, ...), so no tokenization ever decides grouping. Splitting loses nothing, because a merge rebuilds any run, while a run never split cannot be cut later.
- Grouping is the grammar's job. A span slot is a run of one or more tokens, re-joined as text. So a slot handed `B C D` tries both the object phrase `(ObjectN) C (ObjectN+1)` and `B C D` reconcatenated as one name.
- An action template `A (Object1) C (Object2)` makes one candidate per place its fixed word can cut (`A B C (D C E)` and `A (B C D) C E`), multiplied by the candidates each object phrase returns recursively.

**Payoff, stated at the observable output.** `put pig in a blanket on the plate on the table` (tokens `put | pig | in | a blanket | on | the plate | on | the table`) produces every reading below, and each world commits the one it allows:

| Destination cut | Object1 | Object2 | Readings |
| --- | --- | --- | --- |
| 2nd `on` | `pig in a blanket on the plate` | `the table` | the meal, already on the plate, placed on the table; a pig in (the blanket on the plate) placed on the table |
| 1st `on` | `pig in a blanket` | `the plate on the table` | the meal placed on the plate on the table; a pig in a blanket placed on the plate on the table |
| `in` | `pig` | `a blanket on the plate on the table` | a pig put into the blanket on the plate on the table |

Each row multiplies by Object2's own readings (`plate on table` as a qualifier chain, or one merged name).

- In a world with a "pig in a blanket" object and a plate on the table, the meal ends on the plate (asserted on the player's line and the graphs).
- In a world with a pig and a blanket, the qualifier readings are judged by the dry run like any other.
- Kept as they are: `take cup from table` with the cup on the floor still answers "The table has no cup."; `take man in the moon from table` takes it; `put cup on saucer on table` commits the reading the world allows (`qualifiedTakePayoff.integration.test.ts`, `phraseCoveragePayoff.integration.test.ts`).

## Why now

The two consequences of the principle (more candidates, which pressures Identify, and a divider set that spans templates) need design work. They are the right design work: both questions arise in any parser of this language, so answering them once gives them one home. Most of today's fixes answer questions that exist only because of this pipeline's shape (user and assistant, 2026-10-25).

It also serves step 2 of the ladder's [orchestration proposal](AGENT.objectManipulationIterations.planning.md#proposal-deterministic-first-then-an-orchestration-loop-2026-10-25) ("templates match against the text"): one engine over the finest tokenization makes the fast path and the LLM route the same matcher by construction.

## What exists (read from code, 2026-10-25)

The pipeline:
1. **Fast path** ([`discriminateIntent/deterministicChecks.ts`](../../../../../lambda/ephemera/dataSource/actions/discriminateIntent/deterministicChecks.ts) `maybeDeterministicManipulationIntent`). The membership pattern and the containment template's pattern are matched against the text (`matchPatternAgainstString`), behind routing gates; each fill is flattened back to a draft (`draftFromPattern`) and handed up as `ObjectManipulationIntent.skeletons`.
2. **LLM route** ([`parseCommand.ts`](../../../../../lambda/ephemera/dataSource/actions/parseCommand.ts)). Classify, then the intent rows (`matchNonObjectManipulationTemplate`), the Navigation regex (`plan/matchNavigationParaphrase.ts`), Parse (one flat skeleton), Plan, then AcmeOrder (`plan/matchAcmeOrderFamily.ts`).
3. **Plan** ([`plan/planSkeleton.ts`](../../../../../lambda/ephemera/dataSource/actions/enrich/objectManipulation/plan/planSkeleton.ts)). Each stamped skeleton is matched against every `AttemptTemplate` (`matchPatternAgainstTokens`); each fill is a reading; `build(captures)` makes an attempt, and `lowerQualifiers` adds `containedBy` assertions keyed by `stableRefKey`.
4. **Producer** ([`compileAttemptsFromSkeleton.ts`](../../../../../lambda/ephemera/dataSource/actions/enrich/objectManipulation/compileAttemptsFromSkeleton.ts)). Recovers each attempt's kind from its content (`kindOf`), then filters (entry checks, exact-fill precedence, the membership unread-span gate) before Identify, the dry run and selection.

The epicycles, which the slices retire:
- **Two engines, one element vocabulary, different meanings** ([`deterministicTemplate/patternTemplate.ts`](../../../../../lambda/ephemera/dataSource/actions/deterministicTemplate/patternTemplate.ts)). A text wildcard takes one or more words, a token wildcard exactly one token; `objectPhrase` gives flat cuts on text and nested readings on tokens; a fixed word may sit anywhere in the text but must equal a whole token (so `hurriedly into` fails); `rest` is checked last-only in the token engine alone. The fast path therefore matches twice: text, flat draft, stamp, tokens.
- **Positional captures; roles unread.** Builders read `optionAt(captures, 0)` and `spanAt(captures, 3)` ([`plan/templateCaptures.ts`](../../../../../lambda/ephemera/dataSource/actions/enrich/objectManipulation/plan/templateCaptures.ts)); the look builder reads `captures.length - 1` so two patterns can share it. `role` is declared on elements and read only by `assembleIntent`.
- **Template kind discarded, then inferred.** `planSkeleton` drops the template name; `kindOf` infers it (last action narrates: look; transfer with no `containment`: membership). "The primary action is the last" is relied on by `kindOf`, `transferOf` and `commandAttempt/lookedAtObjectId.ts`.
- **Over-generation corrected downstream.** Membership's `rest` lets the pattern match anything; the producer's BD-20 gate drops fills whose tail holds a span. Exact-fill precedence chooses a segmentation inside compile. `stableRefKey` is derived from span text so keys agree across fills, which is what lets one Identify serve them all.
- **Match policy outside templates.** `claimsMembership` destructures captures by position, holds a `take hold` regex and a room-label check for `get`. Containment and spread share `placingPattern` and avoid each other only by disjoint verb lists.
- **Several template and matcher kinds.** `DeterministicTemplate` (one fill or `noMatch`; `makeDeferPatternTemplate` has no users), `AttemptTemplate` (one attempt per fill), a Navigation regex, a hand-written AcmeOrder matcher (no repetition element), bare-word regexes in `deterministicChecks.ts` duplicating the bare-word rows. `deterministicTemplateRegistry`, the bare-word `lookTemplate` and `predictTemplate` have no live caller.
- **Lexicons scattered.** `MEMBERSHIP_VERBS`, `PLACING_VERB_FORMS`, `CONTAINMENT_PHRASES`, `SPREAD_PHRASES`, `QUALIFIER_PREPOSITIONS`/`QUALIFIER_OPTIONS` (with `out` read as `out of`), two inline look-verb lists that differ, `drop` in two verb lexicons with different meanings, two exports named `lookTemplate`.
- **Bookkeeping.** Fills deduplicated by `JSON.stringify` in three places; an intent-classification result type (`ObjectManipulationIntent`) carries parse output.

Not epicycles, only misplaced (they need a home, not deletion): `out` means `out of`, containment and spread must not both claim one command (homes: the elements' typed lexicons, SM-6). The `take hold` and `get` gates were read the same way when this plan opened; 3a retired them instead (no gates, now in [`actions/AGENT.contract.md`](../../../../../lambda/ephemera/dataSource/actions/AGENT.contract.md#qualifier) "What the fast path claims").
